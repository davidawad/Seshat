SESHAT — AGENT NOTES
=====================

WHAT THIS IS
------------
Seshat: a free flashcard / spaced-repetition study app. Local-first, zero-backend — no account,
nothing to authenticate, no server. All data (sets, cards, review history, settings) lives entirely
in the visiting browser's localStorage and never leaves the device.

CONSOLE API (window.seshat)
----------------------------
Open the browser devtools console on this page and call window.seshat directly:
  listSets(), listCards(setId), exportSet(setId), exportSetSimple(setId),
  importSet(json), importSimpleJson(raw, setName?), exportAll(), importAll(json, mode)
  (mode is "merge" or "replace")
Reads/writes localStorage directly, then dispatches a window event the app listens for, so an open
tab updates live. If something still looks stale, reload once.

QUICK IMPORT VIA URL (recommended for a browser-driving agent)
----------------------------------------------------------------
Append a set as JSON to the `import` query param on any URL on this site and the app imports it,
navigates to the new set, and cleans the param from the URL. No login, no file upload, no console
needed.

  Param name:  import
  Param value: encodeURIComponent(JSON.stringify(setJson)) — plain URL-encoded JSON, not base64.

  Two accepted JSON shapes:

  1) Simple (recommended for quick use):
     {"name": "My Set", "terms": [{"term": "Q", "definition": "A"}, ...]}

  2) Full Seshat export format (supports cloze/mcq card kinds too):
     {"seshatExportVersion": 1, "name": "My Set", "description": "", "tags": [],
      "cards": [{"prompt": "Q", "content": {"kind": "short-answer", "answer": "A",
      "acceptableAnswers": []}, "explanation": null, "sourceRef": null, "tags": []}]}

  Minimal example (append to any URL on this site, e.g. this site's root or /sets):
    ?import=%7B%22name%22%3A%22My%20Set%22%2C%22terms%22%3A%5B%7B%22term%22%3A%22Q%22%2C%22definition%22%3A%22A%22%7D%5D%7D

  Size note: keep the whole URL under roughly 8KB for reliability across browsers. Image-occlusion
  cards embed a full data: URL image and are not realistic to build this way.

WEBMCP (IN-PAGE TOOLS)
----------------------
Where the browser exposes WebMCP (document.modelContext per the W3C Web Machine Learning CG draft of
2 October 2026; older flagged Chrome builds expose navigator.modelContext, which is also tried), the app
registers these tools via registerTool(). They act through the running app's own state, so the open tab
updates live (unlike window.seshat). Arguments are validated; failures return {"error": ...} with
isError true instead of throwing.
  list_sets()                      sets with id, name, description, tags, cardCount, memorized, due, new
  list_cards({setId})              cards of one set
  get_settings()                   current settings
  update_settings({patch})         change settings; unknown/out-of-range fields reject the whole call
  import_set({json})               simple {name, terms} or full set export (same parser as ?import=)
  export_set({setId})              one set as set-export JSON
  export_all()                     whole-app backup object (settings, sets, cards, review history)
  import_all({json, mode})         restore a backup; mode "merge" (default) only adds missing sets/cards,
                                   mode "replace" DESTROYS current data (flagged consequentialHint)
  navigate({to, setId?})           to: home | sets | stats | docs | about | set (set needs setId)
Tool results are {"content":[{"type":"text","text":"<JSON>"}]}. JSON arguments are strings, capped at 25M
characters. Browsers without WebMCP register nothing; use ?import= or window.seshat instead.

SCHEMAS
-------
JSON Schema for both accepted import shapes (simple {name, terms} and full seshatExportVersion 1):
  schema/set-import.schema.json   (relative to this file)
Generated from the app's own Zod schemas at build time, so it cannot drift from the importer.

HOW TO DRIVE THE UI (browser-driving agents)
---------------------------------------------
- Prefer ?import= above over clicking through the importer; it is one navigation.
- Routes: / (home), /sets, /sets/:id, /docs, /attributions, /licensing. Study modes are launched
  from a set's page.
- Interactive elements use native buttons, links and form controls with accessible names, so
  role + label locators (e.g. getByRole('button', { name: ... })) are stable. Prefer those over CSS
  classes, which are not a stable interface.
- data-testid attributes are PLANNED for key controls; they do not exist yet.
- Everything is client-side: a fresh browser profile starts empty, and data from one profile or
  origin is invisible to another (dev server vs. deployed site are different origins).
